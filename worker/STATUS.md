# worker — status

Works: all five methods of `worker-request` on the real code; 20 tests, replies validated against `worker-reply.schema.json`.
Run: `nix-shell -p dotnet-sdk_8 bubblewrap git --run 'worker/verify.sh'` (prepares `worker/work/sb`: clone, worktrees old/h2283/h2234, their builds; then restore with network, build and test without).
Passes from a fresh clone with an empty package folder, and after a partial run: `setup.sh` writes `wt/<v>.ready` only after restore and build succeed, redoes both when it is missing, and retries a failed build once after a forced restore. The sample is restored with `-p:Configuration=Release` (a plain restore misses `CSharpIsNullAnalyzer`, NETSDK1064).
Errors: every failing request (bad JSON, unknown method, bad params, exception) gets an error reply with its id; the process never exits on a request. A `commit` that differs from the worktree's HEAD (read from its git files) is an error reply (all methods but `run`).
Process: `dotnet witness-worker.dll` (from `worker/src/Witness.Worker`, net8.0, Roslyn 4.12.0). One request per stdin line, one reply per stdout line, same id; logs go to stderr. Paths in requests are worktree folders the worker can read; `NUGET_PACKAGES` must hold the sample's restored packages (netstandard.library 2.0.3, PolySharp, Roslyn 4.12.0 ...). Env `WITNESS_BWRAP`, `WITNESS_DOTNET` name the binaries for round trips (else PATH).
Measured (2283): GetObjectInfo 673/677 blocks, 3,548 operations, 45 graphs, 0 errors, ~1.1 MB reply; TypeCollector.cs binds with 0 errors on old, 2283, 2234; 28 `reportDiagnostic` call sites; warm generate-only run 44 ms for both sides; round trip 42 → 0 in a bwrap child.

Interface
- `cfg`: `kind` is Roslyn's `OperationKind` name, `symbol` the documentation ID of the original definition. Extra fields: `capture` (flow capture number per graph), `name` (local, parameter, argument), `operator`, `conversion` (`implicit`/`explicit`/`try-cast`), `constant`, `matchedType`, `implicit`, `virtual`, `diagnosticId` (on a `FieldReference` of type `DiagnosticDescriptor`: the constant `id` argument of the field's initializer, omitted when unresolved; e.g. `MemberNeedsKey` → `MsgPack004`; `BothStringAndIntKeyAreNull` and `KeysMustBeUnique` → `MsgPack005`, as the sample's source declares); on a lambda leaf `graph` names its nested graph `<method>/lambda@line:col`; local functions are `<method>/local:<name>`. Blocks add `region`, `reachable: false`, `rethrow`, `thrownType` (type of the thrown expression on a `throw` block, through the semantic model when the operation is untyped). `positionalParameter` on a `PropertyReference` of a positional record property (index of its primary-constructor parameter). Lambda/local-function graphs carry `hash` and the `FlowAnonymousFunction` leaf `graphHash` (SHA-256 of the whitespace-collapsed lambda text; equal when a lambda only moved). Graphs list `maybeNullLocals` (reference-type locals some path assigns `default`/`null`, also through a conditional's flow capture) and those `LocalReference`s carry `maybeNull: true`. `errors` lists compile errors in the file and every None/Invalid operation. Method names: `Type.Method`, `Type..ctor`.
- `references`: names from `changedMembers` that a part's lines reference, with their symbol IDs; without `changedMembers`, every source member referenced.
- `dependencies`: edge A→B when B's lines use a member A declares or a value A writes, or when a local B writes is consumed outside both blocks by a statement using A's member (site = that statement). `version` both/old/new; `changed` when only one version has it, its sites differ, or A's text differs. `reach[].callSites` counts call sites outside the block of members it declares or fields it writes; extra `reach[].sites` lists them.
- `facts`: syntax only, over production files (not under tests/benchmark/sandbox/samples): public types and members, signatures, new .cs files, projects, Package/ProjectReferences, `DiagnosticDescriptor` IDs, constructor assignments whose value changed (`changed-wiring`). Type and member facts span their whole declaration and carry `container` (`T:` ID of the enclosing type, if any). One `new-diagnostic` per new descriptor field (`symbol` = field, `new` = `diagnosticId` = resolved ID, located at the field); the descriptor's and its `…Id` const's `public-member` facts carry `diagnostic: "<id>"` for folding. 2129: 2 public-type, 10 public-member (8 marked), 4 new-diagnostic, 2 new-file, 1 new-project, 1 new-dependency.
- `run`: per side its own collectible load context; lib compiled without generators, app with generators and analyzers; `buildProperties` become `build_property.*` options, `NoWarn` suppresses, `Nullable` sets the context (default off). Round trip only when the side has no error: app plus an injected entry point emitted to a temp folder and run as `bwrap --unshare-all ... dotnet App.dll`; `pid` is that child. The probe is the app's static `Probe.Make()`; `sent`/`received` are JSON dumps of the object.

Deviations and fallbacks
- Fixture differences (fixtures were written before the worker): operation kind `FlowCapture`, not `FlowCaptureOperation`; 2283 edge b1→b2 is `both` (old line 239 also feeds line 985); b1→b3's site is 1080 (where the diagnostic built at 1077 is handed to `reportDiagnostic`), not 1077; reach b2 and b3 are 0, not 1 (their only uses are inside the block).
- "Generated resolver only" reports `generated-and-builtin`: the generated resolver alone cannot format `string`, so primitives come from `BuiltinResolver`; the dynamic resolver is never used. A type with no generated formatter still fails with "not registered".
- Pass-through plumbing through an unchanged member is not collapsed into one edge (change-map scenario); only the statement-level case above.
- Analysis loads the owning project with the netstandard2.0 recipe from `research/spikes/roslyn-cfg-check.md`; projects that need other references bind partly and list errors.
- 2234 is built generator-only, so the 2234 NoWarn scenario is not tested here (group 11 runs it).
