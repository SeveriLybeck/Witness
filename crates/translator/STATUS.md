Pipeline per change (X = old or new; F = file; one unit per production `statements` part P of F inside a changed method M):
1. Worker: `{"method":"cfg","params":{"checkout":…,"methods":[M, every member part's Type.member, every Type..ctor of F]}}` → `cfg.X.json`.
2. From the cutter's `parts.json` (production parts of F): `--inline <member>` for every part with `kind: member` (bare names work); `--derive-delegates <all changed lines of side X, comma list>`; `--part <lines>` per part (`deletedLines` for old, `addedLines` for new); `--site <lines of P on side X>`.
3. `translator lower --cfg cfg.X.json --unit Type.M --version X --site … --inline … --derive-delegates … --part … > model.X.json` (unit id `Type.M#<first site line>`; `--unit-id` overrides).
4. `nix-shell -p cargo rustc gcc pkg-config z3 --run 'cargo run -q -j 2 -p differ -- --old model.old.json --new model.new.json --out rows.json --detail detail.json'`.
5. `translator scope input.json` with `{changedLines, production:[{side,file,line}], models:[{file, model}]}` → `scope.json`.

Model conventions (matched to `crates/differ`): opaque names are `<short>_<hash of symbol/arity>`, identical across versions; a unit's value is its body's result (no `value` wrapper; `value` is `Nullable.Value` with contract `nullable-value-null`); `x as T` = `isnull x ? none : (T:T(x) ? x : none)`; hard cast = `cast` + `failed-cast`; `report` name = descriptor syntax, args = the other `Diagnostic.Create` arguments; `Diagnostic.Location` of a created diagnostic is its location argument (null = Location.None); void calls (e.g. `List.Add`) are `seq` effects; `if` = `[cond, then, else]`, `let` = `[value, rest]`.

- The enclosing `if (intKey == null && stringKey == null)` at :983 is outside the `#985` region (its false arm bypasses the site); conditions on it are not part of the rows.
- X2: an unsupported operation marks its location not modelled and stands in as an opaque `unmodelled` call.
- X3: null-receiver only for receivers from `as`, default, `*OrDefault`, `T?`, cleared after a false `IsNull`; `failed-cast` only on explicit reference conversions.
- X4: outside `--per-iteration` a back edge inside a lowered graph makes its span not modelled (`loop`). The whole loop body is never one unit (paths multiply); a per-iteration unit is the site region within one iteration.
- `lines.modelled` holds lines of the unit's file only; without `--part` it is the lines of lowered statements.
- Hand-reduced CFGs in `tests/fixtures/mod.rs` remain for unit tests; the real replies are in `tests/data/`.

Unit rule support (used by `integration/proof`)
- Closed per-iteration region (`--per-iteration --exact`, `close_region`): the caller gives old and new the same line range (all changed sites of one `foreach` body). The region gets one entry (side entries pull in their predecessors, 2234: back to `if (searchFirst)` :998) and one way on (a `continue` beside the fall-through extends it until one block is left, the iteration's unchanged tail, which stays outside). Reaching the loop header while a tail exists is the effect `region:skip` (leaving the loop: `region:leave`). Locals the region assigns that are live after it are `carried` on the closing `nothing` (extra fields `carried`, `carriedNames`; the differ compares them, Lean ignores them). Without `--exact` the old per-site behaviour (`extend_back`) is unchanged.
- A changed line inside the region's line range with no operation of its own (`continue;`, a brace) is modelled (an edge of the lowered graph). A part hit by a not-modelled range lists its other lines as `in a change with a not-modelled operation`; a part inside a multi-line lambda that was not inlined is `lambda body not compared`.
- Readable conditions: `if` carries `syntax` (source text of the test), `nullTest`, `line`; `index`, `cast`, `value` and contract calls carry `syntax`.
- A string local or parameter that the graph tests against null is sort `OptString` (nullable). An opaque used with a second sort signature is a second function (name from key and signature).
- Modelling conventions: a positional record property (worker `positionalParameter`) of an object built in the unit reads back its constructor argument (2234 `member.IntKey`); `_` pattern is true; `$"…"` is an opaque function of its holes; a `throw` takes the block's `thrownType`; a lambda value is `delegate:<16 hex of the worker hash>` (moved = same value, changed text = other value); a local with worker `maybeNull` (or in `maybeNullLocals`) is nullable: a call on it gets `null-receiver`, a string is `OptString`.
- Worker `errors`: `method … not found` is ignored, `unrecognised operation … at file:line` makes that line not modelled, anything else is a compile error (whole unit not modelled). An `unrecognised operation` that is a `throw` whose block has `thrownType` is modelled.
- `translator scope` input takes `reasons: [{side, file, line, endLine, reason}]` (`scope_with`): a changed line no model covers gets that reason instead of `outside compared units`.
- Not done: a whole method containing a loop is not one unit (`loop`); lambda bodies that are not inlined are not compared (only their hash).
